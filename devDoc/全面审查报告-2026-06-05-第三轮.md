# novel-ai 项目全面审查报告（第三轮）

> 审查时间：2026-06-05 15:20  
> 审查范围：Vue 3 前端项目、IndexedDB 数据闭环、路由页面闭环、后台任务闭环、核心 Composable / Utils 逻辑  
> 验证方式：源码走读 + `npm run build` 生产构建验证  

---

## 一、结论摘要

本轮审查确认：项目经过前两轮修复后，**生产构建可以通过**，后台任务系统的若干历史严重问题已经修复，例如：

- `BATCH_CHAPTER_GENERATION` 已纳入全局面板可执行任务类型。
- `runningSessionIds` 双源状态已移除。
- 全本生成跳章问题已通过 `findNextMissingChapterNumber` + 重试机制缓解。
- 章节后处理已允许已完成后重新触发。
- 后台任务写库已通过 `runTaskWrite(taskId, writer)` 做同任务串行化。

但仍发现一些**页面逻辑不闭环 / 运行期 bug / 数据备份缺失 / 老旧任务系统残留**问题。最需要优先处理的是：

1. `ChapterDetail.vue` 连贯性评分功能未实例化 `useCoherenceScore()`，点击评分必然报错。
2. `Settings.vue` 导出/导入只覆盖小说和章节，其他大量业务数据会丢失，备份功能不闭环。
3. `NovelDetail.vue` 的“生成任务”Tab 仍使用旧 `generationTasks` 队列，和当前全局后台任务系统割裂。
4. `ChapterCreate.vue` 大纲预生成模板直接访问 `chapterOutline.foreshadowing.plant`，AI 返回缺字段时页面会崩。
5. 设置页保存的 `timeout` 没有被 `api.js` 真正使用，用户配置与实际请求行为不一致。

## 三、严重问题（建议优先修复）

### 🔴 1. `ChapterDetail.vue` 连贯性评分功能必然运行时报错

**文件：** `src/views/ChapterDetail.vue`

#### 问题位置

文件顶部只导入了：

```js
import { useCoherenceScore } from '@/composables/useCoherenceScore'
```

但没有执行：

```js
const { scoring, scoreResult, suggestions, runCoherenceScore } = useCoherenceScore()
```

模板和函数中却直接使用了：

- `scoring`
- `scoreResult`
- `suggestions`
- `runCoherenceScore`

#### 影响

- 页面渲染时会出现 Vue 模板访问未定义变量的警告。
- 点击“开始评分”时，`runCoherenceScore` 未定义，会直接抛出 `ReferenceError`。
- 连贯性评分功能对用户不可用。

#### 修复建议

在 `ChapterDetail.vue` 中补充组合式函数实例化：

```js
const {
  scoring,
  scoreResult,
  suggestions,
  runCoherenceScore
} = useCoherenceScore()
```

同时模板中 `scoreResult.level` 当前是对象 `{ text, color }`，直接渲染会显示 `[object Object]`。建议改为：

```vue
<a-tag :color="scoreResult.level.color" size="large">
  {{ scoreResult.level.text }}
</a-tag>
```

### 🔴 2. 设置页数据备份/恢复功能不完整，导致业务数据丢失

**文件：** `src/views/Settings.vue`

#### 问题位置

导出逻辑只导出：

```js
const novels = await db.novels.toArray()
const chapters = await db.chapters.toArray()
const settings = localStorage.getItem('novelAISettings')
```

导入逻辑也只清空/恢复：

```js
await db.novels.clear()
await db.chapters.clear()
```

#### 实际项目中还存在大量业务表

- `characters`
- `characterRelations`
- `foreshadowing`
- `generationTasks`
- `timelineEvents`
- `plotBranches`
- `worldTemplates`
- `inspirations`
- `bookmarks`
- `annotations`
- `outlines`
- `plotLines`
- `outlineEvents`
- `backgroundTasks`
- `novelBibles`

#### 影响

用户点击“导出备份”以为备份完整，但导入后会丢失：

- 角色信息
- 角色关系
- 伏笔
- 时间线
- 大纲编辑器数据
- 阅读书签与批注
- 灵感工作台数据
- 后台任务历史与全本生成状态
- 小说圣经

这是典型的**页面功能说明与实际数据闭环不一致**。

#### 修复建议

导出/导入应覆盖 `db.tables` 中所有表，例如：

```js
const exportTables = {}
for (const table of db.tables) {
  exportTables[table.name] = await table.toArray()
}
```

导入时按表名清空并 `bulkPut`，同时保留版本号和兼容迁移逻辑。

### 🔴 3. 小说详情页“生成任务”Tab 使用旧队列，与全局后台任务系统割裂

**文件：** `src/views/NovelDetail.vue`  
**关联文件：** `src/composables/useGenerationQueue.js`

#### 问题现象

`NovelDetail.vue` 中仍然使用：

```js
import { useGenerationQueue } from '@/composables/useGenerationQueue'
```

并展示 `generationTasks` 表中的任务。

但当前主要生成链路已经切换到：

- `useBackgroundTask.js`
- `useBackgroundTaskPanel.js`
- `GlobalFullGenerationPanel.vue`
- `backgroundTasks` 表

#### 影响

用户在详情页看到的“生成任务”Tab 不是当前后台面板中的真实任务，可能出现：

- 全局面板显示正在运行，但详情页任务列表为空。
- 详情页旧任务的暂停/继续/取消按钮只改 `generationTasks`，不会影响 `backgroundTasks`。
- 用户误以为任务已暂停/取消，但实际后台任务仍在执行。

#### 修复建议

二选一：

1. **移除旧任务 Tab**，统一通过全局后台面板展示任务。
2. 或将详情页任务 Tab 改为读取 `useBackgroundTask().getTasksByNovel(novelId)`，并复用 `useBackgroundTaskPanel` 的执行/重试/删除逻辑。

### 🔴 4. 章节大纲预生成模板直接访问嵌套字段，AI 缺字段会导致页面崩溃

**文件：** `src/views/ChapterCreate.vue`

#### 问题位置

模板中直接访问：

```vue
v-model:value="chapterOutline.foreshadowing.plant"
v-model:value="chapterOutline.foreshadowing.resolve"
```

#### 问题原因

`chapterOutline` 来自 AI JSON：

```js
chapterOutline.value = JSON.parse(jsonMatch[0])
```

但 AI 返回并不能保证一定包含：

```js
{
  foreshadowing: {
    plant: [],
    resolve: []
  }
}
```

#### 影响

一旦 AI 返回缺少 `foreshadowing` 字段，模板访问 `chapterOutline.foreshadowing.plant` 会触发运行期错误，导致页面交互中断。

#### 修复建议

解析后做规范化：

```js
const normalizeChapterOutline = (outline = {}) => ({
  title: outline.title || '',
  summary: outline.summary || '',
  scenes: Array.isArray(outline.scenes) ? outline.scenes : [],
  keyEvents: Array.isArray(outline.keyEvents) ? outline.keyEvents : [],
  cliffhanger: outline.cliffhanger || '',
  foreshadowing: {
    plant: Array.isArray(outline.foreshadowing?.plant) ? outline.foreshadowing.plant : [],
    resolve: Array.isArray(outline.foreshadowing?.resolve) ? outline.foreshadowing.resolve : []
  }
})
```

并在赋值时使用：

```js
chapterOutline.value = normalizeChapterOutline(JSON.parse(jsonMatch[0]))
```

## 四、中等问题

### 🟡 5. 设置页保存的请求超时时间没有被 API 层使用

**文件：**

- `src/views/Settings.vue`
- `src/stores/app.js`
- `src/utils/api.js`

#### 问题现象

设置页允许用户配置：

```js
timeout: 180000
```

store 默认值为：

```js
timeout: 1200000
```

但 `api.js` 中 axios 实例硬编码：

```js
const apiClient = axios.create({
  timeout: 1800000
})
```

流式请求使用 `fetch`，没有任何超时控制。

#### 影响

用户在设置页修改超时时间后，实际 AI 请求不会按用户配置生效。

#### 修复建议

让 `callAI` / `callAIStream` 接收 `timeout` 参数，并由 `useAI` 从 store 传入：

```js
const timeout = options.timeout || appStore.settings.timeout
```

axios 请求使用：

```js
apiClient.post(url, payload, { timeout })
```

fetch 流式请求使用 `AbortController`。

### 🟡 6. 小说创建页“保存并一键生成全本”的完成提示逻辑不可达

**文件：** `src/views/NovelCreate.vue`

#### 问题位置

```js
await startFullGeneration(id, fullGenPrompt.value)
if (fullGen.phase === 'completed') {
  message.success(...)
}
```

#### 问题原因

`startFullGeneration()` 当前只是创建 `FULL_NOVEL_GENERATION` 后台任务并发出 `TASK_CREATED`，不会同步等待整本小说生成完成。

#### 影响

该 `completed` 判断通常不可达。用户只能看到“已在后台开始”，不会在当前逻辑中触发完成提示。

#### 修复建议

把这段完成提示移除，或改为监听任务状态事件后提示。

### 🟡 7. 顶部搜索框、用户菜单存在“假入口”

**文件：** `src/App.vue`

#### 问题现象

- 顶部“搜索小说...”输入框只维护 `searchText`，没有实际搜索行为。
- 通知按钮 `BellOutlined` 无行为。
- 用户菜单中的“个人中心”“退出登录”无行为。

#### 影响

页面交互不闭环，用户点击后没有反馈。

```js
message.info('该功能暂未开放')
```

或者移除这些入口，避免误导用户。

### 🟡 9. 阅读进度百分比在章节号不连续时不准确

**文件：** `src/composables/useReader.js`

#### 问题位置

```js
return Math.round((currentProgress.value.chapterNumber / chapters.value.length) * 100)
```

#### 问题场景

如果章节号不连续，例如只有第 1、3、5 章，阅读第 5 章时：

```text
5 / 3 * 100 = 167%
```

#### 修复建议

按章节列表索引计算：

```js
const index = chapters.value.findIndex(ch => ch.chapterNumber === currentProgress.value.chapterNumber)
return index >= 0 ? Math.round(((index + 1) / chapters.value.length) * 100) : 0
```

## 五、轻微问题 / 优化建议

### 🟢 10. API 层存在生产环境 console 输出

**文件：** `src/utils/api.js`

```js
console.log(`${config.name} API完整响应:`, response)
console.log(`${config.name} API返回的内容:`, content)
```

影响：可能泄露生成内容、污染控制台、影响性能。建议开发环境下再输出：

```js
if (import.meta.env.DEV) console.log(...)
```

### 🟢 11. `callAIWithRetry` / `callAIStreamWithRetry` 已实现但未接入主调用链

**文件：** `src/utils/api.js`

当前 `useAI.generate()` 调用的是：

```js
callAI(...)
```

不是：

```js
callAIWithRetry(...)
```

影响：重试配置存在但实际主业务没有使用。建议统一接入重试版本，或删除未使用代码以降低维护成本。

---

### 🟢 12. `Settings.vue` 清除数据库后未关闭 Dexie 连接

**文件：** `src/views/Settings.vue`

当前：

```js
indexedDB.deleteDatabase('NovelAIDB')
```

若 Dexie 当前连接未关闭，删除可能被浏览器阻塞。建议：

```js
db.close()
indexedDB.deleteDatabase('NovelAIDB')
```

并提示用户刷新。

## 七、建议修复优先级

### P0：立即修复

1. 修复 `ChapterDetail.vue` 的 `useCoherenceScore()` 未实例化问题。
2. 修复 `Settings.vue` 备份/恢复只处理 novels/chapters 的问题。
3. 修复 `ChapterCreate.vue` 对 AI 大纲字段的规范化，避免缺字段崩溃。

### P1：近期修复

1. 移除或改造 `NovelDetail.vue` 旧 `useGenerationQueue` 任务 Tab。
2. 接通设置页 timeout 与 API 层实际请求超时。
3. 给 App 顶部搜索/通知/用户菜单补齐行为或移除入口。
4. 增加路由 404 fallback。

### P2：优化

1. 移除生产环境 `console.log`。
2. 主业务接入 `callAIWithRetry` / `callAIStreamWithRetry`。
3. 优化大 chunk 拆分。
4. 阅读进度改为按章节索引计算。

## 八、总体评价

项目当前已经具备较完整的小说生成、章节生成、后台任务、阅读器、设置、灵感工作台等模块，核心架构方向是合理的。前两轮修复明显改善了后台任务的状态一致性。

但从“业务闭环”角度看，仍有几个高风险点：

- 部分页面功能入口存在但未接通真实逻辑。
- 新旧任务系统并存，容易误导用户。
- 数据备份功能不覆盖完整业务数据，风险较高。
- AI 返回结构缺乏统一 normalize，容易由模型不稳定输出触发页面崩溃。

建议下一步先修复 P0，再统一任务展示与数据备份模型。
