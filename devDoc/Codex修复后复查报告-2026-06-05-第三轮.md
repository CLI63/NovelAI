## 三、仍需立即修复的问题

### 🔴 1. `NovelCreate.vue` “保存并一键生成全本”点击必报错

**文件：** `src/views/NovelCreate.vue`

#### 问题位置

当前解构：

```js
const {
  start: startFullGeneration,
  isRunning: isFullGenRunning
} = useGlobalFullNovelGeneration()
```

但后续仍使用：

```js
if (!fullGen.checkApiKeySetup()) {
  message.warning('请先在设置中配置 API Key')
  router.push('/settings')
  return
}
```

#### 问题原因

`fullGen` 未定义。Codex 移除了 `fullGen` 解构或未保留它，但没有同步修改 API Key 检查逻辑。

#### 影响

用户点击“保存并一键生成全本”会直接抛出：

```text
ReferenceError: fullGen is not defined
```

该功能不可用。

#### 建议修复

方案 A：保留 `fullGen` 解构：

```js
const {
  fullGen,
  start: startFullGeneration,
  isRunning: isFullGenRunning
} = useGlobalFullNovelGeneration()
```

方案 B（更推荐）：直接复用当前页面已有 `checkApiKey()`：

```js
if (!checkApiKey()) return
```

因为 `checkApiKey()` 已经会提示并跳转设置页。

### 🔴 2. `ChapterDetail.vue` 上一章/下一章 computed 使用方式错误

**文件：** `src/views/ChapterDetail.vue`

#### 问题位置

当前代码：

```js
const { prev: prevChapter, next: nextChapter } = computed(() => {
  if (!chapter.value || !chapters.value?.length) return { prev: null, next: null }
  return getPrevNextChapter(chapter.value.chapterNumber)
})
```

#### 问题原因

`computed()` 返回的是一个 `ComputedRef`，形如：

```js
{ value: { prev, next } }
```

不能直接从 `computed()` 返回值上解构 `prev` / `next`。

当前 `prevChapter` 和 `nextChapter` 实际会是 `undefined`。

#### 影响

- 页面上的上一章/下一章按钮会一直处于禁用或不显示状态。
- `handlePrev()` / `handleNext()` 中访问 `prevChapter.value` / `nextChapter.value` 时可能抛错：

```text
Cannot read properties of undefined (reading 'value')
```

#### 建议修复

改为两层 computed：

```js
const prevNextChapter = computed(() => {
  if (!chapter.value || !chapters.value?.length) return { prev: null, next: null }
  return getPrevNextChapter(chapter.value.chapterNumber)
})

const prevChapter = computed(() => prevNextChapter.value.prev)
const nextChapter = computed(() => prevNextChapter.value.next)
```

## 四、新增/遗留的中低风险问题

### 🟡 3. 顶部搜索框只支持回车搜索，点击搜索图标后输入再失焦会隐藏但不搜索

**文件：** `src/App.vue`

当前搜索输入：

```vue
@pressEnter="handleSearch"
@blur="searchVisible = false"
```

问题不严重，但交互上用户可能输入后点页面其他地方，搜索框消失且搜索词保留但未执行。

建议：增加一个明确的搜索按钮，或在 blur 时如果有关键词则执行搜索/清空关键词。

---

### 🟡 4. `Settings.vue` 导入确认弹窗期间 loading 状态提前结束

**文件：** `src/views/Settings.vue`

`handleImportData()` 在解析文件并打开 `Modal.confirm()` 后，会进入 `finally` 将 `loading.value = false`。真正导入发生在用户点击确认后的 `onOk` 中。

这不影响数据正确性，但按钮 loading 不能覆盖整个导入流程。建议在 `onOk` 内单独维护 loading 状态。

---
